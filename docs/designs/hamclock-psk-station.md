# Callsign-specific PSK Reporter feed — #287

The global collector uses PSK Reporter's `v2raw_1pc` MQTT sample. Its latest 200 rows cannot establish who heard a particular station. `/api/spots/psk-station?callsign=N0TEST` retrieves a separate callsign-specific 24-hour snapshot for the forthcoming OF/BY station controls and WSJT-X heard-by report. The global collector and modeling pipeline are unchanged.

The public [PSK Reporter retrieval documentation](https://pskreporter.info/pskdev.html) supports `callsign` (both sender and receiver), a negative `flowStartSeconds` up to 24 hours, and recommends retrieval no more often than five minutes. One canonical uppercase callsign is the cache key. Age, direction and band controls must filter that same snapshot locally; they must not create separate provider requests. Portable callsigns are exact, including suffixes.

The endpoint requests 1,000 rows, reads at most 2 MiB under a ten-second deadline covering headers and body, strictly parses XML, rejects error/DOCTYPE/malformed envelopes, and retains at most 1,000 report objects throughout parsing using bounded newest-first insertion. A bounded read-only provider check showed `rptlimit=1` returning 993 reports, so the application enforces its own limit. It exposes `limited` at the retained ceiling and `discarded` for invalid, unrelated or out-of-window records. **Counts describe loaded reports, never a guaranteed complete history.** Missing SNR/locators remain null. Frequencies preserve integer Hz.

Success, successful empty, stale last success, and unavailable are distinct. `fetchedAt` advances only on success; `checkedAt` records attempts. Success and failure both impose a five-minute cooldown. The snapshot includes `retryAt` so clients can respect the same cadence. Stale rows retain original observation timestamps; consuming views must filter against the current clock even during outages.

The provider quota is shared across callsigns and callers. Every server instance uses the same Supabase/Postgres gate and snapshot cache through service-role-only RPCs. `psk_station_claim` serializes on one gate row, returns a cached station snapshot when fresh, or grants exactly one upstream lease. Competing stations retain prior data as stale or report unavailable until the shared retry time. The lease reserves ten seconds for request start plus five minutes of cooldown; a late start is refused. Publication starts a fresh five-minute cooldown from completion and fences out superseded or duplicate leases. A failure or crash never releases the reservation early. The database cache and each process cache retain at most 128 stations; fresh process entries are not evicted to admit new calls. Requests rejected at capacity do not consume an upstream claim. Endpoint reads remain limited to 30 per client per minute; provider starts are governed by the shared gate, not a per-caller quota.

Deployment prerequisite: manually apply `supabase/migrations/20260907010000_psk_station_cache.sql` and configure server-only `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. All instances sharing provider egress must use the same database. Browser clients receive no database key or lease token. The endpoint fails closed if shared coordination is absent or unavailable; there is no process-local provider bypass. The portable/LAN route needs the same configured cache. This quota limits multi-user refresh throughput; the UI exposes stale/unavailable instead of treating a blocked request as zero receptions. Production migration application remains a maintainer task, not performed by these checks.

`saxes` 6.0.0 and its existing `xmlchars` dependency are promoted from the lockfile's test dependency tree to production; their locked versions and integrity hashes are unchanged. No shared `node_modules` install was performed. The endpoint is registered in the portable manifest, so local dev and the LAN bridge serve the same handler.

Validation: 19 focused handler/RPC tests cover parsing, exact frequency/time, callsign matching, limits, cache capacity, cross-handler coordination, late-start refusal, fail-closed credentials/RPC responses, stale data and body deadlines. `node scripts/check-psk-station-cache.mjs --confirm-disposable-psk-postgres` additionally passed permissions, cache reuse, failure cooldown, duplicate/superseded lease fencing, 128-station capacity, migration reapplication and ten concurrent PostgreSQL callers with exactly one upstream grant. This uses one pinned, labeled, network-disabled container with no host mounts or published ports and removes it afterward. No deployed database or hardware service was touched. UI work and map integration follow in separate slices.
