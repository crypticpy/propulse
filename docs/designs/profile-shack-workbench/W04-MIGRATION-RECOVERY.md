# W04 migration capture, recovery and parity contract

> This is the planning checkpoint. The implemented local contract and remaining acceptance gates are recorded in [W04 local verification](W04-LOCAL-VERIFICATION.md) and the [storage package README](../../../src/lib/station/workbench/storage/README.md). Proposed interface names below are not the current API.

Status: implementation checkpoint for [W04 #177](https://github.com/crypticpy/propulse/issues/177), inspected at baseline `4812bff1`. This document defines required behavior and test evidence; it does not report a completed migration, deployed authorization check, or owner-data rehearsal. No owner records were accessed to prepare it.

The [domain decisions](DOMAIN-DECISIONS.md#5-migration-and-recovery-strategy) require capture → staging → validation → parity report → generation commit. The [preservation register](FEATURE-PRESERVATION.md) is the field-level acceptance ledger. A valid new archive alone cannot prove that everything in its sources survived. Every source record must have a mapped destination, retained recovery destination, or both, with an explicit disposition.

## 1. Capture the sources before their readers change them

Capture is independent of canonical graph validation. Invalid JSON text, unknown schema versions, missing IDs and dangling graphs are capture results, not reasons to replace a source with an empty object. Read the named raw browser keys and database records before importing modules that hydrate/migrate the old stores, invoking sync pulls, or calling settings import. Existing runtime state is a separate observation if already hydrated; never label it the original persisted source.

These local stores and the old image database are not account-keyed. A current login is not proof that every browser record belongs to that account. The capture manifest records the explicitly selected owner, source browser/device, capture context and ownership status. Unattributed or conflicting-account data remains an isolated recovery source until attribution is established; it is never silently attached to the next signed-in user. Do not enumerate authentication storage, decrypt credentials, or include auth tokens in the migration operation. Named raw source files may themselves contain old private/secret fields; retain those only in protected owner recovery artifacts, never logs, issue attachments, test fixtures or public projections.

Map preferences are a different domain: `propulse-active-preset-id` / `mapStore.activePresetId` and remote `preferences._mapPrefs.activePresetId` select map region/camera presets, not shack presets. They must not participate in station identity mapping. Retain existing map preferences untouched; capture any independently requested full settings export as an auxiliary artifact, not a station selection.

The backend capture boundary must return all fields for the authenticated owner, including unknown JSON fields. These are full captures with pagination/completion evidence, not the legacy delta pull using `since`. Record the source table, row identity, owner column, capture request/version information and row content before any `rowTo*` mapper. A failed/incomplete table capture is different from a confirmed empty table. A missing row in a partial pull is never a tombstone.

The first nine tables and JSON locations above are grounded in [shackSync](../../../src/lib/sync/modules/shackSync.ts); image metadata/objects are grounded in [imageSync](../../../src/lib/sync/modules/imageSync.ts). Preserve both the complete containing row and embedded snapshot, connected by source path; a snapshot does not erase contradictory columns. A snapshot whose ID disagrees with the row identity is an identity conflict, not an instruction to rename another item.

The current legacy endpoints do not provide a transactional multi-table snapshot. Capture records that limitation. A future capture RPC may provide a consistent snapshot; until then, use an account migration/write barrier and verify source versions/digests again before sealing. A source changed during capture produces a new capture/alternative, not a partially mixed generation. LocalStorage, separate IndexedDB databases, remote SQL and object storage cannot share one browser transaction.

### Media capture and reference closure

1. Read every record of IndexedDB database `propulse-images`, version 1, object store `images` (key path `id`). Retain original `StoredImage` ID, blob bytes/type, width, height, `createdAt`, declared `sizeBytes`, actual byte count and digest. [imageStore](../../../src/lib/db/imageStore.ts) exposes `getAllImageIds` and `getImage`; do not restore through `storeImageWithId` if preserving original metadata, because it assigns a new creation timestamp.
2. Capture all owner `user_images` rows and blobs from bucket `equipment-images` at each row's actual `storage_path`. The conventional upload path is `{userId}/{imageId}.jpg`; do not replace a captured path with a guessed path or infer a public URL. Retain missing/denied/download-failed states separately, with retry context and row metadata. A blob without metadata is a separate object-store reconciliation case; prove any owner-prefix listing is complete before claiming all remote objects were captured.
3. Reference ledger entries retain the source owner/context, containing record/revision and exact field path, role, image ID or URL, and array index. Source roles include `imageId` for all equipment; ordered `galleryImageIds` for radios/antennas/accessories; profile `profileImageId` and `profileImageUrl`; legacy `photos` URLs. New canonical roles additionally include `primaryImageId`, compatibility `imageIds`, gallery, receipts and manual media. Preserve duplicate role references and gallery ordering while separately counting distinct blobs.
4. Capture currently unreferenced local blobs too: old deletes, incomplete records or older raw snapshots can make them recoverable data. Unattributed blobs remain in private recovery, not automatically assigned to an account or uploaded. Do not run orphan cleanup as part of migration.
5. Same image ID with different local/remote bytes is a conflict, even when dimensions/byte sizes match. Retain both content variants and their source paths/digests. Identical bytes with different IDs may share storage internally only if every original ID/reference survives. Missing media never causes removal of the containing gear/profile field.
6. Verify backup media by reading exported/staged bytes and recomputing digests. A manifest of names alone is not a complete backup. Missing originals may be explicitly recorded as pre-existing unavailable content, but do not call them recovered; any exception to a complete-media cutover gate must appear in the owner-reviewed parity disposition.

## 2. Capture identity, schema and integrity

The following are requirements for the common manifest contract that the integration owner will freeze, not a second independently implemented shared schema.

| Record | Required information and invariant |
| --- | --- |
| Capture manifest | Manifest format/version; stable capture/migration ID; explicit owner binding and device/source context; capture start/end instants; app/build revision; independent source schema versions; ordered source entries and media/reference manifests; completeness/availability for every requested source; digest algorithms/encodings; immutable capture seal. |
| Source entry | Stable source locator (`localStorage` key, table + primary key, blob database/store/key, explicit file path within backup); original payload artifact; presence/read/parse result; source schema version if present, otherwise explicit unknown; content digest; parent row + JSON path for snapshots; observation time/version. An array occurrence index distinguishes duplicate IDs without silently overwriting either occurrence. |
| Mapping entry | Owner + source namespace + source kind + source identity/occurrence; canonical destination kind/ID, adapter version, source digest; decision status (`mapped`, `needs-review`, `quarantined`, or retained-only); diagnostics; resolution record and any equivalence/alias evidence. One input may have a canonical destination **and** raw recovery destination. |
| Stage/generation | New generation ID; immutable capture/mapping/adapter manifest digests; validated record set; quarantine alternatives; media retention references; expected previous reader pointer; parity report and its reviewed dispositions; stage seal. Altering a source, mapping or decision requires a new stage seal. |
| Diagnostic / decision | Stable ID; source locator/digest and exact path; code/severity; affected canonical IDs/active context; original alternatives; chosen treatment and evidence; resolver identity/context and time. A text message alone is not the only link back to a field. |
| Recovery artifact | Owner-bound manifest and all required raw/staged/post-cutover record bodies, revision ancestry and clone-source closure, blobs or explicit availability records, mappings/diagnostics, operation receipts and pending outbox. Restore must verify artifacts before admitting them to any active generation. |

Use SHA-256 over a documented byte representation, with domain/version tags. Original localStorage strings require an encoding that preserves JavaScript code units; a UTF-16LE code-unit representation (no BOM) does so even for unpaired surrogates. If the implementation chooses UTF-8, reject or separately retain non-round-trippable strings before hashing rather than silently replacing characters. Files/blobs are hashed over their exact bytes. Keep the original raw string/file even when parsed JSON is available: whitespace, duplicate object keys, numeric spelling and malformed content cannot be reconstructed from `JSON.parse`.

For SDK-returned remote rows, the source is the unmodified returned JSON value, not an alleged byte-for-byte PostgreSQL storage image. Hash a specified deterministic JSON encoding (recursive sorted own object keys, array order unchanged, finite JSON values only); retain the captured response artifact when available. JSONB may already have normalized original input formatting/duplicate keys. Raw-capture digests and canonical comparison digests are separate fields; a units conversion is not raw equality. Do not use a parse/sanitize/`JSON.stringify` round trip as proof of original-byte preservation. Own `__proto__` keys and unknown nested JSON survive recovery parsing; non-JSON runtime values remain outside canonical JSON with an explicit unavailable-capture diagnostic and retained external source where one exists.

IDs and time enter adapters explicitly and are stored before retryable work. Do not use fresh UUIDs or `Date.now()` on every transform retry. Keep valid physical instance identities where possible; when source IDs collide or an old model-only radio needs an instance ID, allocate through the owner-scoped persistent mapping ledger. A radio model ID is not a physical radio identity. Catalog models are captured from the referenced catalog build; custom models and every original source citation are retained. Reimport of the same source identity/digest and mapping version returns the same result; changed content yields a reviewable version/alternative, not a second accidental item. Matching make/model/name alone never merges two physical radios.

Source schema versions remain independent: shack 5, profile 12, settings 36, monolithic user historical versions, settings backup 1, and canonical workbench version are not interchangeable. Unknown/newer versions are raw-captured and reported as unsupported; do not stamp them with today's version. Repeat capture of an unchanged source may reuse content-addressed artifacts, but retains its separate observation provenance.

## 3. Transformation without invented topology

Use the [W02 adapters](../../../src/lib/station/workbench/equipment/legacyAdapters.ts) `mapLegacyEquipment` and `mapLegacyRadioModel` with explicit owner/source ID/version/capture time/target ID. Their compile-time coverage ledgers are in [legacyFields](../../../src/lib/station/workbench/equipment/legacyFields.ts). Stage returned values, evidence, raw sources and every diagnostic together. `needs-review` is not permission to discard the unknown field; `quarantined` is not permission to discard the record. Invalid retirement dates/chronology are quarantined rather than converted to owned gear.

W02 converts feet/inches to meters, microvolts to volts, MHz passbands to Hz, millivolts to volts and square feet to square meters; retain both raw and canonical values and verify conversion once. Keep known zero/false, signed dBi/dBm and source map keys. Legacy SWR is declared, not measured. Tested specifications remain attributed reports with explicitly incomplete context; preserve every source citation including unclassified/unreferenced ones. Amplifier duty cycle remains unknown with CR10 diagnostics because existing source values and percent display disagree. No magnitude heuristic chooses fraction versus percent.

Column-only remote inputs need explicit field-by-field extraction with row provenance before invoking compatible adapters, or a separate reviewed row adapter. Do not invoke current `rowTo*` defaults and call their result raw. Keep the original remote row as an additional recovery artifact even if a normalized adapter input is produced. Absence in a poorer remote record does not erase richer local/snapshot data. Conflicting present values remain two named alternatives; “snapshot preferred” and “newer timestamp wins” are not conflict-resolution policies.

### Presets, chains and locations

- Preserve `StationPreset` radio/antenna/optional feedline IDs, ordered inline IDs, accessory IDs, power, linked location, notes and creation time; preserve `StationChain` ordered nodes, run IDs/base cables/inline order, side accessories and the same metadata. Keep raw envelopes for the entire setup and individual runs (FP13).
- There are **two existing conversion identity conventions**: [shackStore migration](../../../src/stores/shackStore.ts) produces chain ID equal to preset ID and random run ID; [stationPresetToChain](../../../src/lib/station/stationPresetToChain.ts) produces `preset:<presetId>` and `preset:<presetId>:feedline`. Recognized relationship plus compatible content can map to one logical setup with both provenance entries. Matching IDs/prefixes alone does not prove equivalence when content disagrees; matching names/gear never proves it. Preserve divergent versions as alternatives and keep the active source relationship explicit.
- W02 intentionally returns no invented ports or internal paths. Ordered legacy adjacency documents intended sequence, not actual connector identities, switch common/throw wiring or a measurement. Preserve that sequence in recovery/association data; admit canonical connections only when endpoint/path identities are explicitly supported or separately reviewed. An incomplete canonical setup may contain its full known equipment membership with no claimed RF route. Do not auto-create placeholder ports merely to make a graph parse.
- Include base cables and every ordered inline item in membership, plus all `shackAccessoryIds`; preserve power supply, grounding, rotator, keyer and audio/DSP as unwired associations. A preset accessory moved out of a legacy RF list requires a recorded CR06 classification correction, not silent list erasure. Unknown categories remain preserved for review.
- Duplicate run/member IDs, missing references, contradictory inline order or ambiguous switch branches remain complete raw recovery records plus diagnostics. Valid unsupported graph documentation remains saveable with reasons via [assessRevisionTopology](../../../src/lib/station/workbench/revisions/inputs.ts); invalid references do not become a partial fabricated canonical graph. A structural candidate is not an engine-supported, reviewed operating selection.
- Map locations with stable owner-scoped identities and exact name/type/grid/coordinates/timezone/activation reference/creation date/raw metadata. `activeLocationId:null` means use home. Preserve the `current-location` slot across repeated GPS updates and preserve its dirty mutation token until acknowledged. Missing creation date or legacy-only synthetic `legacy-home` is diagnosed, not given an invented historical date from a hook. Location identity removal must respect historical revision references; home protection and owner mirrors remain compatible until W08 consumers migrate (FP26).
- Existing editor layout is captured only where an actual persisted source exists. Chain node order is electrical intent, not saved canvas coordinates. Current W03 list/diagram/rack layout records can be carried unchanged when importing a canonical archive. Do not invent a legacy saved layout or treat auto-layout output as captured source data.

### Active-context parity is its own gate

Capture all three shack selectors (`activeChainId`, `activePresetId`, `activeRadioId`) separately, including dangling/null values, and every actual candidate they reference. Capture the selected model and instance `specPreference`, global `preferTestedSpecs`, requested power and linked location; the station's active/home IDs, full saved-location records and legacy mirrors; relevant settings and any pending location mutation token. Preserve remote `is_active`/active IDs as separate observations, not precedence overrides.

[useStationCastContext](../../../src/hooks/useStationCastContext.ts) currently prefers a resolved active chain, then lifts an active preset; `resolveStationCastLocation` tries the chain link, then preset link through nullish selection, and falls back to active location if that selected link does not resolve. [useActiveLocation](../../../src/hooks/useActiveLocation.ts) uses active-or-home ID and can synthesize a legacy-home object with default coordinates/current creation time. Capture the raw inputs and record the actual selector output/provenance separately; do not promote those synthesized values into original location evidence. `activeRadioId` still supplies other consumers independently.

The parity report compares equivalent source selections and resolved inputs across OC01–OC16, identifying intentional correction cases CR04/CR09 separately from accidental differences. An ambiguous or incomplete active source leaves the legacy operating reader active. Do not choose another setup, default to 100 W, clear selection, or treat imported route order as reviewed operation. Existing QSO entries and any logging during coexistence retain the exact source/version used. CAT telemetry and map/editor selection are not authorization to change station operation. HamClock receives existing compatible selector outputs; no display edits are part of this migration.

## 4. Restartable stages and repository integration

These boundaries align with the repository/backend checkpoint documents and remain proposed API names until the integration owner freezes shared contracts. They must not create an independent migration transaction protocol.

1. **Capture:** establish owner/source context and a stable migration ID; record named-source availability; capture raw text/rows and media metadata/bytes; write immutable artifacts and read them back. Capture completion requires full source enumeration or explicit unavailable-source status. A restart resumes unfinished source/artifact work by stable locator and digest; it never overwrites a differing captured artifact.
2. **Transform into staging:** use a versioned adapter set and persistent ID mapping; write proposed records, evidence, history, untouched profile/auxiliary recovery payloads, raw graphs and diagnostics into an inactive generation. Checkpoint each batch and its digest. No legacy store, remote source row or image is deleted or overwritten.
3. **Validate:** parse the entire staged aggregate, not only individual item shapes; check owner isolation, unique IDs, model/evidence closure, retained source bibliography, snapshot isolation, graph endpoints/run reciprocity/orientation, layout membership, revision ancestry, retirement chronology and location identities. Quarantine invalid sources outside valid topology. Verify recovery artifacts/media bytes again. Invalid canonical data blocks generation sealing.
4. **Compare/report:** account for every input record/field and reference; compare FP rows, known/unknown states, units, media roles/order/counts/digests, QSO associations and active-context interpretation. List every missing/ambiguous source, intentional correction and owner decision. A retained-only private profile field is accounted for but is not evidence that its new UI shipped. Any source change since capture or unresolved cutover-affecting conflict invalidates the seal.
5. **Seal/stage generation:** `stageGeneration` stores an immutable validated generation manifest tied to capture/mapping/adapter versions, backup and parity report references, required media availability and expected previous pointer. Staging may be large/batched; the seal only appears after those durable records are complete. Sealed generation contents cannot subsequently mutate.
6. **Activate locally:** `activateGeneration({operationId, expectedPointer, stageId, sealDigest})` verifies the seal and compare-and-swap precondition and commits pointer/generation metadata, operation receipt/history and outbox entry in one IndexedDB transaction. No network fetch or blob export occurs inside that transaction. An unavailable/invalid backup or stale pointer yields no pointer change. Successful local commit is distinct from cloud acknowledgment.
7. **Sync/acknowledge:** transport the same versioned operation contract used by normal repository writes. The backend authorizes owner, enforces immutable versions and expected heads/pointer atomically, and returns an operation-specific receipt or conflict. Same operation ID + digest is idempotent; same operation ID + different content rejects. An older acknowledgment cannot clear a newer operation. Legacy full-blob station writers cannot simultaneously author migrated state; old-client capability/schema gates are required before actual cutover.

The provisional common operation envelope is `{schemaVersion, operationId, ownerId, generationId, payloadDigest, createdAt, expectedHeads, records, nextHeads, tombstones}`. Expected heads use explicit kind/identity/version, with null meaning expected absence; tombstones retain expected versions and reference checks. Migration activation must use the root-frozen operation/receipt contract and canonical digest rules, rather than another envelope with similar field names. W03 `expectedHead` proposals feed those transactional preconditions; preparing a proposal is not committing it. Current clocks remain audit information rather than a conflict resolver.

Local repository boundaries under discussion are `openStationRepository({ownerId, ...deps})`, `readSnapshot`, `commit`, `listOutbox`, `recordSyncResult`, `stageGeneration`, `activateGeneration`, `exportRecovery`, and `close`. Sign-out/account switch closes the owner handle and isolates subsequent reads/outbox work. Old legacy queues are captured and reconciled separately; do not inject their unverified payloads directly into the new outbox or discard pending QSO work because station migration succeeded.

## 5. Recovery and rollback behavior

| Boundary | Required input/result and invariant |
| --- | --- |
| Inspect/resume migration | Migration ID + owner context returns durable stage/checkpoints, source availability, mapping/diagnostics, seal/commit receipt and pending work. If pointer commit succeeded before the caller received a response, report that receipt rather than rerunning transforms with new IDs. |
| Export recovery (`exportRecovery`) | Export requested generation(s), immutable capture artifacts, source/mapping/decision ledgers, every retained revision including parent/clone-source closure, private metadata/profile payloads, media/reference manifest and bytes/availability states, operation receipts, conflicts/tombstones and pending outbox. Include versions and digests; report partial/failed output explicitly. A downloadable file's existence alone is not success. |
| Verify/import recovery | Parse the manifest format/version, verify artifact bytes/digests and owner context, enumerate dependencies/missing media, and stage into a new inactive generation. Same artifact + mapping version is idempotent. Unsupported/newer formats remain recoverable without changing the active pointer. Do not call `importSettings` to overwrite live stores as a substitute. |
| Repair quarantined graph | Source diagnostic + raw artifact + explicit user-supplied corrections produces a new staged proposal, linked to the untouched original. Validate the complete repaired aggregate; review active-context/media parity again. Never destroy the original when repair succeeds. UI belongs to subsequent editor work; W04 supplies the durable records/API behavior. |
| Resolve conflict | Preserve base, local and remote versions/operations with names/IDs and impact references. A resolution is a new versioned operation with fresh expected heads, not silent last-write-wins or timestamp sorting. Reopening/retrying yields the same alternatives until resolved. |
| Rollback/forward recovery | First seal/export a recovery branch containing **all** post-cutover records, revisions, tombstones, pending operations and media references. Prefer repair or restore into a fresh canonical generation. If switching the reader back to legacy, preserve that branch and mark new graph features as unavailable to the legacy reader; do not down-convert them silently. Pointer switch requires explicit expected-pointer CAS/receipt, and old/new writers cannot race. |
| Source retention/cleanup | W04 performs no destructive cleanup of original stores/rows/blobs. Later cleanup requires retained-revision/publication/log/media reference closure, verified recovery and a separately explicit retention decision. Missing remote rows and retired items are not cleanup authority. |

If capture/backup verification fails, keep the existing reader/pointer and show a recoverable stage failure. If failure occurs after pointer commit, recover the committed generation/receipt; do not guess the old reader from a stale in-memory flag. Database corruption, newer unsupported schema, account mismatch or digest tampering opens recovery mode without overwriting either original or staged content. Browser quota failure is a failed durable write, not a successful save merely because Zustand still holds the object.

Fixtures use invented IDs, callsigns, locations and tiny generated blobs. Use existing [W02 adapter tests](../../../src/lib/station/workbench/equipment/legacyAdapters.test.ts), [W03 fixtures](../../../src/lib/station/workbench/fixtures.ts) and [revision tests](../../../src/lib/station/workbench/revisions/services.test.ts) as inputs, then test the persistence boundary; their current passing tests do not establish W04 behavior.

| Fixture | Concrete contents and required result | Register linkage |

## 7. Evidence boundaries and completion

Synthetic unit/integration fixtures can prove transform determinism, raw-field/byte preservation, mapping identity, archive validity, expected-head semantics, atomic transaction failure, outbox idempotency, media digest accounting and staged recovery. A real IndexedDB test environment is required for transaction abort/reopen/upgrade behavior; an in-memory fake alone cannot prove browser quota, database corruption or cross-tab upgrade handling. Controlled two-client/backend tests must prove authenticated owner isolation, server CAS, tombstone behavior and reconnect receipts; client-provided owner IDs and local tests do not establish RLS enforcement.

W04 acceptance also requires a protected rehearsal with existing owner/development records after raw backup is verified, using an isolated account/browser/worktree context and the repository's [local agent testing guide](../../guides/LOCAL-AGENT-TESTING.md). Record source build/schema versions, capture and artifact digests, record/field/reference parity, media byte availability, active-context differences, deliberate resolutions, crash/restore outcome and deployed backend/app revisions. Publish only sanitized test summaries and identifiers safe for the issue; never the actual backup, coordinates, serials, notes, credential fields or private image bytes.

No source document can prove what data a particular deployed account currently contains, whether an old mapper already lost a value, whether a remote object exists, or whether production authorization works. This checkpoint accessed no such records. Missing historical values must be reported honestly. FP/CR rows remain Pending until their full persistence, consumer and UI gates pass; W04 synthetic success alone does not close W08 operating integration, W05 public/media authorization, W21 deployed parity, or W22 participant validation.
